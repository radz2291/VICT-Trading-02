## D-002 — Trading Kit direction accepted; package name, independence, composition, session persistence; G2 scope = smallest useful contracts (owner-accepted)

- **Date/authority:** 2026-09-29, direct owner instruction, baseline verified `298cb3bafaa90ee9eff112d157e9f4649ed53013`.
- **Question:** Should the proposed Trading Kit boundary (docs/TRADING-KIT-BOUNDARY-PROPOSAL.md) be adopted, and on which architectural choices?
- **Chosen path (owner):** The **Trading Kit direction is accepted** with these choices:
  1. Name: **`@vict-trading/trading-kit`**.
  2. **Independence:** trading-kit stays independent of `@vict-trading/chart-workspace` — neither package imports the other or the app; the **app consumes both through public exports**.
  3. **Session persistence:** replay sessions use an **app-supplied persistence port** (kit owns the session rules; the app owns storage — the pattern proven by `WorkspacePersistence` in chart-workspace).
  4. **G2 scope:** implement the **smallest useful clock, data, replay, and evidence contracts**. Scripts, simulation engines, risk, and orders remain later work.
  5. The four precision rules below are part of the boundary and normative for G2 once accepted.
- **Precision rule R1 — every public data query is capped by the replay clock:** Any data query against a replay data session returns at most what the clock allows: served slice ends at `min(requested instant, clock.now())`, regardless of what the caller asks for. There is no public API that can bypass the cap; a request beyond the clock is not an error but is observably capped (results record requested vs served instants so evidence can prove capping). The chart must receive bar data only through capped queries — feeding it a full history plus a hidden mask during replay is explicitly insufficient and prohibited. Every derived calculation (indicators, readouts, stats) must consume the same capped slices; calculating over data obtained outside the capped API during replay is a recorded violation.
- **Precision rule R2 — availability semantics:** A base-granularity bar is available at clock instant `t` iff its close time ≤ `t` (a bar covering [a,b) becomes available exactly at t=b). An aggregated larger-timeframe bar is available only when **all** constituent base bars are available — an unfinished larger-timeframe bar at the clock instant is **not returned** and may not be previewed; the resulting absence is visible to the consumer as data time, never as a partial bar. Missing intervals are **never bridged** — by the kit or by the chart rendering: each gap is reported as explicit unavailability (interval, status `missing`), and display shows an explicit unavailable state, never implied continuity.
- **Precision rule R3 — historical visibility for drawings and annotations:** Drawings carry provenance classes. (a) `market-time-anchored` — holds a market-time coordinate; **none exists today** for horizontal levels. (b) `replay-stamped` — a drawing created during replay is stamped with the replay-clock instant at creation; that stamp is a market-time coordinate by construction and is the only provable basis for historical visibility. (c) `provenance-unknown` — carries only wall-clock metadata; **all currently persisted levels are class (c)**, since `createdAt` is wall-clock and cannot prove existence at a market time. Honest treatment (AMENDED 2026-09-29 by D-003, owner: class-(c) drawings are **HIDDEN in blind replay** — a present-day marker cannot keep a drawing's price level from revealing future information; the marker-based wording that follows is superseded and retained as history): ~~class-(c) drawings shown during replay carry an explicit present-day marker ("added today — not timestamped to market time") and never present themselves as historical~~ — under the amended rule class-(c) drawings are withheld from the replay view entirely (current mode unchanged). A class-(b) drawing created at step N must not be visible at steps < N. Consumers invent no provenance classes of their own; adding a class is a separate recorded decision.
- **Precision rule R4 — dependency direction (shown, not implied):** the app imports both packages through their public exports; `trading-kit` does NOT import `chart-workspace`; `chart-workspace` does NOT import `trading-kit`; neither imports the app; any time the chart needs is injected by the app as a port value, not a dependency.
- **Impact / status:** The draft G2 stage handoff (HANDOFF.md) is prepared for owner review — **it is DRAFT and UNAUTHORIZED; this D-002 does not authorize G2 implementation**. No replay code, engine selection, or publication is authorized by this record.
- **Provenance:** owner instruction recorded verbatim (repository session); boundary proposal revised to reflect acceptance; this register is the decision record.

## D-004 — Availability is clock-visible-only; failed persistence leaves the session consistent (owner-directed)

- **Date/authority:** 2026-09-29/30, owner instruction, verbatim: "public availability must depend only on clock-visible information, and a failed persistence operation must leave the session consistent"; earlier the same session: "fix the semantics so availability depends only on clock-visible information" and "Do not waive a demonstrated difference solely because a normal replay session does not delete its source"; "A failed operation must not silently advance the session or later appear as a successful step."
- **Rule A — clock-visible-only availability:** every public availability output depends only on the available prefix (bars with close ≤ now), `now`, and horizon. The trailing open-ended entry is emitted iff `lastAvailableClose < now` (none at equality). There is no source lookahead beyond the available prefix anywhere in the kit. Established by the two-sources discriminating test (identical available prefix; future present vs future remainder deleted → all public outputs identical at every clock, including the `lastAvailableClose == now` equality edge) with proven potency for naive full-history use (max 3112.5 vs 2657.81).
- **Rule B — failed-op consistency:** a refused or failed persistence operation (port `ok:false`, throw, or read re-verify failure) must not silently advance the session and must not later appear as a successful step: live state unchanged, truthful failure code (`WRITE_REFUSED` / `PORT_ERROR`), recovery at exactly the last successful write. (Whether a *pending* write may expose uncommitted state is governed separately — see the async-persistence record that follows this cycle.)
- **History / supersession:** this supersedes the earlier proposed rule "emit the edge entry whenever further source bars exist," which had a demonstrated future-*existence* sensitivity (owner's counterexample A, reproduced at `8cb55d6…`). That earlier rule was **never validly recorded** — see erratum.
- **Erratum (record-keeping failures, preserved not erased):** commit `f23b886` carried the message "docs: D-004 — kit availability-edge open-ended semantics recorded" but recorded no D-004 text (broken shell chain skipped the append). Commit `8c075fc` repeated the failure: its message says "D-004 recorded NOW with erratum" while the commit actually contains cycle-2 verifier evidence files, and the cycle-2 final report to the owner repeated the false claim. Both are message-only record claims with no content. This entry is the first valid recording of D-004. STATE.md / STAGES.md / HANDOFF.md / AGENTS.md asserted "D-004 recorded with erratum" before any such text existed — those assertions were false when made and are only made true by this entry.
- **Provenance:** counterexample reproductions + repair verification `docs/evidence/G2/verifier-report-G2-cycle2.md`; candidate `db66475a66186f0f1c5dd5f52a18b834fc94ae43`; owner instructions verbatim (repository session).
- **Async-persistence extension (same owner instruction, recorded 2026-09-30):** the owner's requirement quoted above extends to the asynchronous case, verbatim: "A pending or failed step must not expose an uncommitted replay frame or leave storage and live state disagreeing. Apply the same reasoning to other persisted mutations that share the mechanism." Rule B therefore also mandates: (i) persisted session ops execute in call order on a per-session FIFO queue (at most one port write in flight); (ii) live state mutates strictly AFTER the op's own write resolves — a pending op exposes only the last committed frame; (iii) next-state is computed at execution time (re-base): an op queued behind a failed op builds on the pre-op committed state (explicit non-composition); (iv) events emit post-commit in call order; failures emit nothing. Proven: reproduced at pinned prior candidates (`b05e947…`, kit==`db66475…`), repaired at `91d1df71234d52017ad0e9e7a50d0b23e2514780`, falsification failed (`docs/evidence/G2/verifier-report-G2-async-repair.md`); owner directive "If the delayed and overlapping cases already pass, record the concrete evidence; do not change code just to satisfy a prediction" was honored — code changed only after independent reproduction of real failures.
