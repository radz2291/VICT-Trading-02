## Method notes and trap checks

- **M-1 Input events:** all chart interactions (clicks, drags, wheel, keys) were dispatched as real CDP input events (`Input.dispatchMouseEvent` / `Input.dispatchKeyEvent`, `isTrusted:true` — traced). Where noted, select/input `change` events were synthesized in-page because CDP cannot drive a native `<select>` dropdown menu; this exercised the same event path a real user's selection fires.
- **M-2 Setup trap:** asserted before any interaction that the served page on 5222 contains `data-testid="chart-island"` (G1 marker) and no `lwc-readout` (G0 spike marker). Confirmed: HTTP 200, 6313 bytes, 1× `chart-island`, 0× `lwc-readout`. An old stale tab pointing at :5199 (dead server, old spike URL) was found open in the browser and closed; no stale server was listening (ports 5199/5211 verified closed by netstat).
- **M-3 Clean emulation protocol** (per G0 addendum): stale per-target emulation cleared (`Emulation.clearDeviceMetricsOverride`) before any width measurement; each narrow-width measurement taken as **fresh reload at that width**, then overflow measured from `documentElement.scrollWidth` vs `clientWidth`. Leftover emulation (390×844) was detected on the inherited browser and cleared at session start.
- **M-4 Harness incidents, disclosed:** (a) at ~17:07 local, a duplicated same-URL tab existed in the browser and my CDP helper can pick tabs by URL-prefix; one early observation ("clicking near the line moved the level 2652.97→2653.26, later two unexpected levels") was taken under that ambiguity and **could not be reproduced in any clean run** (see C-4, C-5); attributed to harness tab-contamination plus stale coordinates after the toolbar reflow (F-V2), not claimed as product behavior. (b) The inherited Chrome instance stopped delivering keyboard/button input mid-session; a full Chrome restart restored it — all keyboard evidence below is from the restarted session. (c) The extra Chrome instance I launched (fresh profile, :9223) was closed and its temp profile deleted; the original instance and my preview server were stopped at session end.
